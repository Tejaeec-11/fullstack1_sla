REACT.JS – DAY 1 BASIC NOTES

1. What is React?

React is an open-source JavaScript library used to build interactive and reusable user interfaces, especially for web applications. React was created at Facebook and was open-sourced in 2013. Today it is maintained by Meta and the open-source community. React mainly focuses on the UI layer of an application.

In traditional JavaScript applications, developers manually select DOM elements and update them whenever data changes. React provides a declarative and component-based approach. We describe what the UI should look like for the current data/state, and React handles the necessary rendering and DOM updates.

JavaScript

↓

React

↓

Components

↓

UI

Simple example:

function App() {

return <h1>Hello React</h1>;

}

export default App;

10. What is a Component?

A component is a reusable piece of UI. In modern React, components are commonly JavaScript functions that return JSX.

For example, instead of writing navbar code repeatedly, we can create one "Navbar" component and use it wherever required. Components make applications easier to divide into manageable pieces.

Syntax:

function Welcome() {

return (

<h1>Hello Student</h1>

);

}

export default Welcome;

Arrow function:

const Welcome = () => {

return (

<h1>Hello Student</h1>

);

};

export default Welcome;

15. What is JSX?

JSX stands for JavaScript XML. It is a syntax extension commonly used with React that allows developers to describe UI using HTML-like markup inside JavaScript.

Example:

const App = () => {

return (

<h1>Hello React</h1>

);

};

This:

<h1>Hello React</h1>

is JSX.

Browsers do not directly execute JSX syntax as plain JavaScript. Build tools such as Vite use transformation tooling so JSX is converted into JavaScript that can be executed by the browser.

21. What is Real DOM?

DOM stands for Document Object Model. The browser represents an HTML document as a tree of nodes/elements that JavaScript and browser APIs can interact with.

Example HTML:

<div>

<h1>Hello</h1>

<p>Welcome</p>

</div>

Conceptual DOM tree:

div

├── h1

│ └── Hello

└── p

└── Welcome

This browser-managed tree is what we commonly refer to as the real DOM.

23. What is Virtual DOM?

Virtual DOM is a common term for React's in-memory representation of the UI. React uses its internal tree structures to determine what the UI should look like based on the latest component output.

When state changes, React renders the affected component logic again, creates the next representation, determines the necessary changes, and then commits the required updates to the browser DOM.

Simple concept:

State Change

↓

React Renders

↓

New UI Representation

↓

Compare / Reconcile

↓

Required DOM Changes

↓

Browser UI Updated

---

24. Virtual DOM vs Real DOM

Real DOM| Virtual DOM Concept

Browser's actual DOM tree| React's in-memory UI representation

Browser APIs modify it| Managed internally by React

Actual page changes happen here| Helps React calculate desired changes

DOM operations can involve browser rendering work| React batches/calculates updates before committing

Important interview clarification:

React is not simply "fast because Virtual DOM is always faster than DOM." Performance depends on the application. The important concept is that React provides a declarative rendering model and determines the necessary UI updates for us.

---

25. What is Reconciliation?

Reconciliation is the process React uses to determine how a newly rendered element/component tree relates to the previous one and what updates are necessary.

When props or state change, React renders again. During reconciliation, React compares the new element tree with the previous tree, preserves or replaces component instances where appropriate, and determines what work needs to be committed to the DOM.

Basic process:

Previous UI

↓

State Changes

↓

New Render

↓

Reconciliation

↓

Determine Differences

↓

Commit Necessary Updates

↓

Real DOM

React itself is primarily a UI library. Full applications often combine React with routing, data fetching, build tools, and other libraries/frameworks.

What is a component?

A component is a reusable unit of UI, commonly written as a JavaScript function returning JSX.

Why are components important?

They improve reusability, maintainability, organization, and separation of concerns.

What is JSX?

JSX is a syntax extension that allows HTML-like UI markup to be written inside JavaScript.

Can a browser directly execute JSX syntax as ordinary JavaScript?

No. JSX normally needs to be transformed into JavaScript by tooling before execution.

What is Virtual DOM?

It is the common term for React's in-memory representation of UI used as part of its rendering and reconciliation process.

What is the Real DOM?

It is the browser's actual Document Object Model.

What is reconciliation?

Reconciliation is React's process of determining how a new render differs from the previous one and what updates are required.

What is "App.jsx"?

It is commonly the root application component in Vite React projects, though the filename itself is only a convention.

What is "main.jsx"?

It is commonly the application entry point that creates the React root and renders the root component.

Why should component names start with capital letters?

React uses capitalization to distinguish custom components from built-in/host elements such as "div" and "button".

39. Day 1 Golden Interview Answer

React is an open-source JavaScript library used to build interactive, component-based user interfaces. React applications are divided into reusable components, and JSX is commonly used to describe the UI. Instead of manually updating individual DOM elements throughout the application, developers describe the UI based on data and state, and React manages the rendering process.

When props or state change, React renders the relevant components again and performs reconciliation to determine the necessary changes. Those changes are then committed to the browser's real DOM. In a typical Vite React project, "main.jsx" initializes the React application, "App.jsx" acts as the root application component by convention, and additional components are imported and composed to build the complete interface.

23. What is Virtual DOM?

Virtual DOM is a common term for React's in-memory representation of the UI. React uses its internal tree structures to determine what the UI should look like based on the latest component output.

When state changes, React renders the affected component logic again, creates the next representation, determines the necessary changes, and then commits the required updates to the browser DOM.

Simple concept:

State Change

↓

React Renders

↓

New UI Representation

↓

Compare / Reconcile

↓

Required DOM Changes

↓

Browser UI Updated

---

24. Virtual DOM vs Real DOM

Real DOM| Virtual DOM Concept

Browser's actual DOM tree| React's in-memory UI representation

Browser APIs modify it| Managed internally by React

Actual page changes happen here| Helps React calculate desired changes

DOM operations can involve browser rendering work| React batches/calculates updates before committing

Important interview clarification:

React is not simply "fast because Virtual DOM is always faster than DOM." Performance depends on the application. The important concept is that React provides a declarative rendering model and determines the necessary UI updates for us.

---

25. What is Reconciliation?

Reconciliation is the process React uses to determine how a newly rendered element/component tree relates to the previous one and what updates are necessary.

When props or state change, React renders again. During reconciliation, React compares the new element tree with the previous tree, preserves or replaces component instances where appropriate, and determines what work needs to be committed to the DOM.

Basic process:

Previous UI

↓

State Changes

↓

New Render

↓

Reconciliation

↓

Determine Differences

↓

Commit Necessary Updates

↓

Real DOM

37. Important Interview Questions

What is React?

React is an open-source JavaScript library for building component-based user interfaces.

Is React a library or framework?

React itself is primarily a UI library. Full applications often combine React with routing, data fetching, build tools, and other libraries/frameworks.

What is a component?

A component is a reusable unit of UI, commonly written as a JavaScript function returning JSX.

Why are components important?

They improve reusability, maintainability, organization, and separation of concerns.

What is JSX?

JSX is a syntax extension that allows HTML-like UI markup to be written inside JavaScript.

Can a browser directly execute JSX syntax as ordinary JavaScript?

No. JSX normally needs to be transformed into JavaScript by tooling before execution.

What is Virtual DOM?

It is the common term for React's in-memory representation of UI used as part of its rendering and reconciliation process.

What is the Real DOM?

It is the browser's actual Document Object Model.

What is reconciliation?

Reconciliation is React's process of determining how a new render differs from the previous one and what updates are required.

What is "App.jsx"?

It is commonly the root application component in Vite React projects, though the filename itself is only a convention.

What is "main.jsx"?

It is commonly the application entry point that creates the React root and renders the root component.

Why should component names start with capital letters?

React uses capitalization to distinguish custom components from built-in/host elements such as "div" and "button".

39. Day 1 Golden Interview Answer

React is an open-source JavaScript library used to build interactive, component-based user interfaces. React applications are divided into reusable components, and JSX is commonly used to describe the UI. Instead of manually updating individual DOM elements throughout the application, developers describe the UI based on data and state, and React manages the rendering process.

REACT ROUTER DOM – COMPLETE BEGINNER NOTES

1. What is React Router DOM?
React Router DOM is a routing library used in React web applications to move between different pages or views without reloading the entire website.

In a normal website, when we click a link, the browser may request a completely new HTML page from the server. In a React Single Page Application, React Router changes the displayed component based on the URL while keeping the application running.

Traditional Website

Page 1
 ↓
Click Link
 ↓
New HTML Page Loads
React Router:

React App
 ↓
URL Changes
 ↓
Matching Route Found
 ↓
Component Changes
 ↓
No Full Page Reload
2. Why Do We Use React Router?
Suppose our React application has:

Home
About
Services
Products
Contact
Login
Dashboard
Without React Router, we may manually show and hide components.

With React Router, every page can have its own URL.

/               → Home

/about          → About

/products       → Products

/contact        → Contact

/login          → Login

/dashboard      → Dashboard
This makes the application behave like a proper multi-page website while still working as a Single Page Application.

3. What is SPA?
SPA means:

Single Page Application
In an SPA, the browser initially loads one main HTML page. After that, JavaScript and React update the UI when the user navigates.

Examples:

React Application

index.html
    ↓
React Loads
    ↓
Home Component
    ↓
Click About
    ↓
About Component
The browser does not need to completely reload the application for every internal page.

52. Important Interview Questions
What is React Router DOM?
React Router DOM is a routing library used in React web applications to map browser URLs to React UI and navigate between views without doing a full-page reload for normal internal client-side navigation.

Why do we use BrowserRouter?
BrowserRouter provides routing context and uses the browser history API for navigation.

What is Routes?
Routes contains route definitions and renders the best matching route branch for the current location.

What is Route?
Route connects a URL path with an element/component.

Difference between Link and anchor tag?
Link is designed for client-side routing within the React application. A normal anchor navigation performs standard browser navigation and can reload the document.

Difference between Link and NavLink?
Link performs navigation.

NavLink performs navigation and provides active/pending state information useful for styling navigation menus.

What is useNavigate?
useNavigate() is a hook used for programmatic navigation.

When do we use useNavigate?
Common cases:

Login
Register
Logout
Form submission
Button click
Conditional navigation
What is useParams?
useParams() returns dynamic route parameters from the current matched URL.

What is a dynamic route?
A route containing variable path segments.

Example:

/product/:id
What is Outlet?
Outlet renders the matched child route inside a parent route/layout.

What is Navigate?
Navigate is a component used to perform declarative navigation or redirects during rendering.

REACT FORM HANDLING – SINGLE OBJECT STATE

1. What is Single Object Form Handling?
When a form has multiple inputs like name, email, age, and city, creating separate state for every input is not always necessary.

We can store all form values inside one object state and use one common handleChange() function to update every input.

Process
Multiple Inputs
      ↓
Single Object State
      ↓
Same handleChange()
      ↓
Update Required Property
      ↓
Form Object Updated
2. Object State
Instead of:

const [name, setName] = useState("");
const [email, setEmail] = useState("");
const [age, setAge] = useState("");
We can create one object:

const [formData, setFormData] = useState({
    name: "",
    email: "",
    age: "",
    city: ""
});
Here:

formData
→ Complete form object

setFormData
→ Updates the form object
3. Important Input name Property
Every input should have a name.

<input name="name" />

<input name="email" />

<input name="age" />

<input name="city" />
The name should match the object property.

Object Property       Input name

name             →    name
email            →    email
age              →    age
city             →    city
This is the important concept for using the same function.

4. Same handleChange() Function
Instead of creating:

handleNameChange()
handleEmailChange()
handleAgeChange()
handleCityChange()
we create only:

const handleChange = (event) => {

    const { name, value } = event.target;

    setFormData({
        ...formData,
        [name]: value
    });
};
The same function handles all inputs.

5. Understanding event.target
When the user types:

event.target.name
→ Which input changed?

event.target.value
→ What value did the user enter?
Example:

If the user types "Arun" in the name input:

name  = "name"

value = "Arun"
If the user types in email:

name  = "email"

value = "arun@gmail.com"
So the same function can identify which property should be updated.

6. Why Spread Operator ...formData?
We should keep the existing object values while updating only one property.

{
    ...formData,
    [name]: value
}
...formData copies the existing form data.

Then:

[name]: value
updates only the input that changed.

Process
Old Object
   ↓
Copy Existing Values
   ↓
...formData
   ↓
Find Changed Input
   ↓
[name]
   ↓
Update its Value
   ↓
New Object
7. Why [name]?
[name] is a computed property name.

Suppose:

name = "email"
Then:

[name]: value
behaves like:

email: value
If:

name = "city"
it behaves like:

city: value
So one function can dynamically update different properties.

8. Complete Example
import { useState } from "react";

const App = () => {

    const [formData, setFormData] = useState({
        name: "",
        email: "",
        age: "",
        city: ""
    });

    const handleChange = (event) => {

        const { name, value } = event.target;

        setFormData({
            ...formData,
            [name]: value
        });
    };

    const handleSubmit = (event) => {

        event.preventDefault();

        console.log(formData);
    };

    return (
        <form onSubmit={handleSubmit}>

            <input
                type="text"
                name="name"
                value={formData.name}
                onChange={handleChange}
                placeholder="Enter Name"
            />

            <input
                type="email"
                name="email"
                value={formData.email}
                onChange={handleChange}
                placeholder="Enter Email"
            />

            <input
                type="number"
                name="age"
                value={formData.age}
                onChange={handleChange}
                placeholder="Enter Age"
            />

            <input
                type="text"
                name="city"
                value={formData.city}
                onChange={handleChange}
                placeholder="Enter City"
            />

            <button type="submit">
                Submit
            </button>

    );
};

export default App;
